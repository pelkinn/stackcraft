# StackCraft

Браузерная игра про системный дизайн. На каждом уровне есть задача от заказчика: лендинг, магазин в Чёрную пятницу, чат, платежи, аналитика. Ты собираешь архитектуру из блоков, соединяешь их стрелками и запускаешь трафик. Симуляция показывает, где система рвётся.

Готового решения игра не подсказывает: цели описаны языком бизнеса («страница открывается мгновенно в любом городе»), а не списком технологий.

## Как играть

1. Выбери уровень на карте кампании.
2. Прочитай бриф и цели справа.
3. Перетащи блоки из палитры на схему. Клик по блоку открывает карточку с описанием, плюсами и минусами.
4. Соедини блоки стрелками от выхода (справа) ко входу (слева). Недопустимые связи отклоняются с объяснением.
5. Настрой число реплик в инспекторе (клик по узлу на схеме).
6. Нажми «Запуск» или пробел. По схеме побежит трафик, перегруженные узлы покраснеют.
7. Смотри отчёт. Разбор узких мест скрыт по умолчанию, чтобы сначала подумать самому.

### Звёзды

- ★ — все цели достигнуты, ошибок не больше 5%.
- ★★ — уложился в лимит серверов и в p95.
- ★★★ — ни одной ошибки, а на уровнях с fault injection схема переживает падение любого узла.

После прохождения или неудачной попытки можно посмотреть эталонное решение. Твоя схема при этом сохраняется, и к ней можно вернуться.

## Как устроена симуляция

Модель потоковая и детерминированная, без случайностей: одна и та же схема всегда даёт один и тот же результат.

- **Трафик** делится на статику, чтения и записи. Пропорции задаёт уровень.
- **Нагрузка узла** считается как `входящие rps / (rps на инстанс × реплики)`. Всё сверх ёмкости отбрасывается и считается ошибкой.
- **Латентность** растёт при приближении к пределу: `база / (1 − загрузка)`. p95 — самый медленный синхронный путь. Очередь считается границей асинхронности, то, что за ней, в p95 не входит.
- **Маршрутизация:**
  - CDN поглощает около 95% статики;
  - кеш снимает 80–85% чтений с базы;
  - поисковый движок забирает часть чтений;
  - если есть очередь, записи идут в неё, а воркер пишет в базу пачками.
- **SPA и статика — это файлы.** У них нет своего rps, их обязан отдавать Nginx или CDN. SSR-фреймворки считаются серверами.
- **Бюджет считается в серверах.** Каждый свой инстанс — один сервер. Файлы, CDN, внешние и managed-сервисы стоят ноль. Поэтому выбор стека важен: Go выдержит нагрузку на двух серверах там, где Laravel понадобится семь.
- **Fault injection** роняет узлы по одному: stateless-узлы, а на отдельных уровнях ещё базы и кеши. У базы с репликой срабатывает failover.

## Стек

- React 19, TypeScript, Vite
- [React Flow](https://reactflow.dev) (`@xyflow/react`) — холст со схемой
- Zustand — состояние игры, прогресс и черновики в localStorage
- Framer Motion — анимации
- [simple-icons](https://simpleicons.org) — логотипы технологий
- WebAudio — звуки синтезируются на лету, без аудиофайлов
- Vitest — тесты движка

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # тесты движка
npm run build    # проверка типов и сборка в dist/
```

## Структура

```
src/
  data/
    blocks.ts      каталог из 60+ технологий: rps, латентность, серверы, теги
    tech.ts        описания, плюсы и минусы для карточек
    logos.ts       логотипы из simple-icons и свои глифы
    levels.ts      10 уровней: трафик, цели, лимиты, эталонные решения
  engine/
    rules.ts       какие связи допустимы и почему
    simulate.ts    потоковая симуляция и fault injection
    evaluate.ts    проверка целей, звёзды, разбор
    graph.ts       хелперы для проверки целей
    engine.test.ts тесты: эталоны берут 3★, цели не подсказывают решение, баланс стеков
  store/game.ts    Zustand: схема, прогон, эталон, прогресс
  components/      палитра, холст, узлы, рёбра, HUD, модалки
  screens/         карта кампании и экран уровня
  audio/sfx.ts     синтезированные звуки
```

## Как добавить уровень

1. Добавь объект в `LEVELS` в `src/data/levels.ts`: бриф, трафик, лимит серверов, p95, режим fault injection.
2. Опиши цели через хелперы из `engine/graph.ts` (`linked`, `reaches`, `has`). Формулируй цели как задачи бизнеса, без названий технологий. Тест проверяет это автоматически.
3. Добавь эталонное решение в `reference`. Тесты проверят, что оно проходит на 3★.

## Как добавить технологию

1. Добавь блок в `src/data/blocks.ts`.
2. Добавь логотип в `src/data/logos.ts`.
3. Добавь описание в `src/data/tech.ts`.

Тесты упадут, если что-то из этого забыто.
